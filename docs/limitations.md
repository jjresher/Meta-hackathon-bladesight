# Known limitations

What does not work or is not covered, its impact, and the issue that owns it. Shown honestly in
the README and the Evaluation page. See skill `write-decision`.

- The fleet is synthetic: real DTU photos of one Nordtank turbine grouped into 12 turbines for the demo — impact: rankings illustrate the method, not a real farm — issue: #11
- Sizes are relative (pixels and share of blade area), not millimetres: tiles carry no scale — impact: severity relies on relative size and appearance — issue: #6
- Severity has no public ground truth; it is graded against our own illustrative rubric and checked on a small hand-labelled set — issue: #7, #10
- The git/gh restrictions on agents are only partly enforced: the `deny` rules in `.claude/settings.json` are prefix patterns, so flags after the branch name, `git -C <dir> push`, `--amend`, `git config user.*`, `gh api -X ...` and similar are not matched. The rest is enforced by instruction (`AGENTS.md` rule 9) and by GitHub branch protection on `main`, which only the human can configure — impact: an agent could break a rule by accident; the human merges every PR — issue: #1
- Calls that fail are assumed unbilled, which is unverified: (a) an attempt or call that times out after the provider already billed it is released from the spend log as free; (b) a 2xx whose body cannot be parsed (`MetaInvalidResponseError`) is released as free although it was almost certainly billed; (c) a `KeyboardInterrupt` or kill mid-request releases the reservation (a hard kill leaves it counted at its estimate) — impact: the cumulative cap can be off by a few calls; compare with the provider's usage page after real runs — issue: #2
- The spend log is `.spend/spend_log.jsonl` (gitignored): deleting it, or pointing `BLADESIGHT_SPEND_LOG` elsewhere, resets the caps, and a damaged log blocks every call (fail closed) until a human repairs it — impact: manual cleanup, and dropping a line removes its spend from the total — issue: #2
- The inter-process cap lock uses `fcntl` (Linux/macOS); on Windows the cap is only enforced per process — impact: none on the dev machines and CI — issue: #2
- Rate limits (Baseten 15 RPM, Meta 3,000 RPM per team) are handled reactively by backing off on 429/529, not by throttling ahead of time — impact: a burst on Baseten can waste retries — issue: #2
- `meta-sam-parser` is under the SAM License (Meta): attribute it in the README and keep its licence text with any redistribution; Muse Spark box output ("perception grounding") and `POST /v1/responses/input_tokens` are not used — issue: #2
- Still unconfirmed after the real calls (`docs/evidence/meta-api-step1.md`): whether `input_tokens` includes the cached tokens (`cached_tokens` was 0 in every call), `temperature` and the tool-call item shapes on Meta Responses, `store` on SAM requests (not sent; the SAM reply echoes `store: true`), reasoning-effort values other than "low" and the default, Baseten's image input format, its reset-header names and its real rate limits (15 RPM / 100k TPM assumed) — impact: those paths may need small fixes in `http_provider.py`; costs are the documented prices times real usage, not checked against an invoice — issue: #2
- Muse Spark calls default to `store=false` and `reasoning.effort="low"` (both accepted: reasoning 686 to 203 tokens, cost -46% on the same prompt); the quality of grading under "low" is not evaluated and lower values were not tried — impact: re-check severity quality in #7/#10 and override with `META_REASONING_EFFORT` — issue: #2
- SAM mask and box geometry (raster exactly the box size, placed at its top-left, inclusive `x2`/`y2`) was observed on 28 masks over two photos and checked visually, but the mask tokens' `x=0;y=0` are ignored and no blade-defect image was tested; early SAM confidences (0.68-0.95 for cars and turbines, 0.52-0.79 for "rotor blade") come from two images with no ground truth — impact: not evidence for the #3 go/no-go — issue: #2, #3
- The pre-call cost estimate ignores the arguments of assistant `tool_calls` in the input (a small underestimate in multi-turn agent loops; the overshoot is bounded to one call because settlement uses the real usage) — impact: slightly low reservation estimates for the fleet agent — issue: #2, #12
- Enabling DEBUG logging for `httpx`/`httpcore` may print request headers, including the bearer token (not verified): never enable it with a live key; the client's own logs never include headers — impact: key leakage in logs — issue: #2
