# Open weights: Muse Spark Open on Baseten vs the Meta Model API (issue #15)

## What runs on which model

| Stage | Meta run (`replay/`) | Open run (`replay/open-weights/`) |
|---|---|---|
| Box proposals (detection) | Muse Spark `muse-spark-1.3`, Meta Model API | the same stored proposals (reused, no call) |
| Segmentation | SAM 3.1 `sam-3.1`, Meta Model API | the same stored SAM 3.1 masks: SAM 3.1 has no open-weights path here and stays on the Meta Model API |
| Measurement | local code | the same stored measurements |
| Severity (`assess/v1`) | `muse-spark-1.3` | Muse Spark Open `meta-models/muse-spark-open`, Baseten |
| Second look + rule checks (`verify/v1`) | `muse-spark-1.3` | `meta-models/muse-spark-open` |
| Fleet agent (tool calls) and report | `muse-spark-1.3` | `meta-models/muse-spark-open` |

One setting picks the chat model of the last three rows: `--chat-provider baseten` on
`uv run poe fleet ...` or `BLADESIGHT_CHAT_PROVIDER=baseten` (`src/bladesight/chat.py`). Every
`Assessment`, `Verification`, `WorkOrder`, agent step and `Report` records the `model` and
`provider` that produced it, and `GET /api/replays` lists which model ran each stage
(`docs/api.md`). Model id: the account's Baseten `/v1/models` listing (free call, re-checked on
2026-11-03) shows `meta-models/muse-spark-open` and no `-1026` variant. Baseten tool calling
works on its OpenAI-compatible chat completions (checked first with one two-call round trip,
0.0035 USD). Every Open request gets at least 6,000 output tokens because the model always
reasons; the client waits for a slot under the account's 15 requests/minute
(`meta/ratelimit.py`).

## The whole farm on Muse Spark Open

Full numbers: [`open_weights_farm.md`](open_weights_farm.md) (generated by
`uv run poe fleet compare` from the two stored replays). Same 96 detected defects in both runs;
only the chat model changed. n is small (96 defects, 12 turbines, one run per model): these are
agreement counts between two models, and neither is a reference.

| | Muse Spark (Meta Model API) | Muse Spark Open (Baseten) |
|---|---|---|
| Defects graded and verified | 96 of 96 | 96 of 96 (0 errors, 0 retries, 192 calls) |
| Verdicts `ok` / `needs_review` / `reinspect` | 33 / 50 / 13 | 22 / 60 / 14 |
| Agent run | `run-final`: completed, 23 tool calls, 9 work orders (3 repair, 6 re-inspection) | `run-open-weights`: completed, 22 tool calls, 8 work orders (2 repair, 6 re-inspection) |
| Cost: grading + second look | part of the 1.63 USD farm run (detection included) | 1.7406 USD (detection reused) |
| Cost: agent run with its report | 0.0645 USD | 0.0634 USD |

Agreement between the two runs:

- Same severity on **74 of 96** defects (77%), within one level on 85 (89%).
- Same verdict on **63 of 96** (66%). 17 defects are `ok` in both, all 17 with the same severity.
  The open model is more cautious on this farm (fewer `ok`, more `needs_review`).
- Farm ranking (the deterministic score of verified defects): Spearman correlation 0.77 over the
  12 turbines; 4 of the top 6 turbines are the same (T01, T02, T08, T10).
- Work orders: 2 of the 5 defects in any repair order are in a repair order in both runs; 16 of
  the 30 defects in any re-inspection request are requested in both.
- The Open agent wrote no text before its tool calls (0 of 22 calls have a rationale; the Meta
  agent wrote one before all 23) and used 7 model turns instead of 14. Neither run had a call
  rejected by a tool rule.

We do not claim the open model is better or worse: the two runs agree on most grades and on the
shape of the plan, and differ mostly on which borderline defects count as verified.

## Severity gold set (40 crops)

Same 40 gold crops, same labeller's labels, same `assess/v1` prompt, same crops (`gold.crop_for`),
no detector confidence. Models: Muse Spark `muse-spark-1.3` (Meta Model API, low reasoning effort, requests
not stored) and Muse Spark Open `meta-models/muse-spark-open` (Baseten, OpenAI-compatible chat
completions; its id comes from the Baseten `/v1/models` listing of the account: the plan's
`-1026` suffix returned 404). Reproduce: `uv run python -m bladesight.eval.agreement --provider
baseten` (the Meta run: `--provider meta`). Costs are documented prices times real usage, not
invoice-checked. As in `severity_agreement.md`, the labels are one non-specialist applying
`docs/rubric.md`: this is agreement with the rubric applied by that person.

| | Muse Spark (Meta Model API) | Muse Spark Open (Baseten) |
|---|---|---|
| Valid grades | 40 of 40 | 40 of 40 (needs a 6,000-token output budget, see below) |
| Quadratic weighted kappa (95% interval) | 0.12 (-0.05 to 0.29) | 0.19 (0.01 to 0.38) |
| Exact agreement / within one level | 25% / 48% | 30% / 55% |
| Mean (model - human) | -1.30 levels | -1.20 levels |
| Model severity distribution | {1: 29, 2: 6, 3: 5} | {1: 27, 2: 6, 3: 7} |
| Cost of the 40 crops | 0.1515 USD | 0.4195 USD (about 2.8x) |
| Evidence | [`severity_agreement.md`](severity_agreement.md) | [`severity_agreement_open_weights.md`](severity_agreement_open_weights.md) |

- The two models give the **same severity on 32 of the 40 crops** (`eval/gold/model_grades.csv`
  vs `model_grades_open_weights.csv`). Both grade mostly 1 and neither grades above 3.
- The kappa difference (0.19 vs 0.12) is inside the overlap of the two intervals at n = 40:
  we do not claim the open model is better. Both agree only weakly with the rubric as applied by
  the labeller (kappa near zero to 0.4, both grade mostly 1); the open model is **no worse** on this
  small check.
- The comparison is not controlled for reasoning: the API run used low reasoning effort and a
  1,500-token budget, Baseten's model always reasons and had 6,000 tokens. The 2.8x cost ratio
  reflects token volume at the rates in `spend.py` (documented prices), not a hosting-price
  comparison.
- Muse Spark Open reasons before it answers and the reasoning counts against the output budget: at
  1,500 tokens it returned an empty reply on 23 of 40 crops (that first attempt, 0.45 USD, was
  discarded and is why Baseten spend in total is about 0.89 USD); at 6,000 tokens all 40 were valid.
- Baseten image input accepted the OpenAI-style `image_url` data URLs (confirmed on the live API);
  no retry or 4xx on the final run.
- Since then the fleet agent and the report also ran on open weights (above). Detection stays on
  SAM 3.1 through the Meta Model API, which has no open-weights path here.
